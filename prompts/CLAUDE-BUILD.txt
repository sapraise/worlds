MCP AND STATE

Use the real MCP SDK. Implement proposed tools world_get, world_plan, world_build, world_event and world_attach_artifact. These are Worlds tools, not pre-existing Nebula APIs.

world_plan validates and previews. world_build applies only an owner-reviewed revision. world_event receives bounded idempotent run updates. world_attach_artifact references permitted outputs. No arbitrary shell execution, unrestricted files/URLs, or inherited owner permissions.

For local development use a real tested transport on loopback. Choose stdio and/or Streamable HTTP based on the actual client. A cloud Nebula client cannot necessarily reach localhost; do not silently open a tunnel. Test locally with an MCP client/inspector and document remote integration pending if access is unavailable. Hosting and remote authentication belong to the later go-live phase.

Persist stable world/actor/run/event IDs, event timestamps, sequence/attempt where available, provenance, visibility and artifact references. Separate idle/working/needs-input/completed/failed/unknown from freshness and human acceptance. Label sample, agent-reported, runtime-observed and human-reviewed evidence. No success from silence.
